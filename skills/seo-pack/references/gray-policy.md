# Gray-Area Policy

**Gray-area tactics are NEVER named in product copy, docs, or UI.** Implement only the white-hat mechanism, quietly. If a tactic can't be implemented without the gray part, don't implement it.

## Allowed mappings (mechanism only)

| Never say | Quietly implement as |
|---|---|
| "Parasite SEO" | Real, useful content published on high-authority platforms (LinkedIn articles, Medium, industry publications) — genuinely good content, not spam |
| "Indexing tricks" | Fast-indexing surfaces + prompt GSC/Bing submission via API |
| "Churn-and-burn" | Never on client sites. Full stop. |
| "Review manipulation" | Legitimate review-request flows only; monitor and report fakes |
| "Link schemes" | Editorial outreach, expert quotes, podcast guesting — earned mentions only |

## Hard lines
- **Black-hat indexing is forbidden on client sites.** No exceptions, no "just this once."
- Spammy "Best X for Y" output (thin, biased, undisclosed) is forbidden — the geo-citability listicle rules (neutral, competitors linked, sourced, current) are the minimum bar.
- If an agent proposes a tactic from outside this pack, it must pass this test: *"Would we be comfortable explaining this mechanism to the client on a call?"* If no, it's out.

## Why this policy exists
Gray mechanisms often work. Naming them in product/docs creates liability, erodes trust, and trains the team to reach for shortcuts. The mechanism without the name keeps the upside and drops the risk.
